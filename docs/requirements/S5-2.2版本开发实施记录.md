### 3.4 顺带修掉的隐性 bug

`detectQuery` 原来读 `props.modelValue`（要等父组件重渲染才更新）去配**当下**的 `selectionStart` → 识别**慢一个字符**：输入 `/hell` 时菜单还停在 `/hel`。根因是**光标与文本不同源**（与本仓库「列表数字必须与内容同源」是同一判据）。改为把刚输入的值直接传进 `detectQuery(value)`。有单测守住（「查询词按**当前**光标计算，不慢一个字符」—— 用 `/hell` vs `/hel` 的候选数差做判别）。

### 3.5 本轮登记的两个口径

1. **原型 `.composer-box` 与 PRD 冲突**：原型把 textarea 和按钮装进同一个 `--r-lg`(12px) 圆角盒子，而 **AC-R8-05 要求输入框与按钮圆角 = 6px** → 取 PRD，保留「输入框与按钮分开」的结构。这是继「focus ring 2px vs 3px」「Select 弹层」之后第三处「原型 ≠ PRD」，处理方式一致：**AC 为准，差异留档**。
2. **`Textarea.resizable` 是对 M2 冻结接口的增量扩展**：新增可选 prop、默认值不改变任何既有消费方行为。按 S4 §8 第 5 条在此登记，未动既有 prop 语义。

### 4-T.3 本轮判据与发现

1. **联合类型 v-model 的收窄点在 handler**：`Select` 的 `update:modelValue` 是 `string`，而 `TunnelTTL` / `eventMode` / `TaskStatus|''` 是联合类型 → 用 `:model-value` + `@update:model-value="(v) => x = v as T"` 在边界 cast 一次，**状态类型保持精确**（不可表示的非法值不进状态），而不是把 ref 放宽成 string。
2. **`Select` 根元素是 `w-full`**：裸放在 flex-wrap 行里会吞掉整行（TTL、事件保留上限两处踩到）→ 外面套**固定宽壳** `w-32`，不改组件接口。
3. **时间输入保 change 语义**：原实现只在 `@change` PATCH；组件的 `update:modelValue` 是 input 级事件，直接 v-model 会让时间选择器每 tick 打一次 API → 保留 `@change` 透传（fallthrough 到根元素），`:model-value` 单向。
4. **`/tasks` 是移动端专用页**（路由守卫 >768px 重定向仪表盘）→ 桌面视口冒烟报「缺控件」是**假阴性**，冒烟脚本对该路由用 375px 视口。教训入 §6.1 同类：**验证脚本的前提条件要先显式置对**。
5. TasksPage 搜索框：原「磁贴壳 + 透明裸 input」结构拆除，改为 `Input` + 绝对定位放大镜 + `pl-8`（Tailwind 生成序 `pl` 恒在 `px` 之后，左内边距确定性覆盖——同机制全局已用 `px-2 py-1` 这类组合，非新依赖）。

### 4-T.4 冻结接口扩展登记（第 2 条，按 S4 §8 第 5 条）

`Input.defineExpose({ el, focus })`：与 T2 的 `Textarea` 同款结论与同款最小暴露面——`RobotCreateModal` 校验失败时要把焦点送回具体字段（`appIdEl.value?.focus()`），组件实例 ref 拿不到原生元素。纯新增、不影响既有消费方。

### 5-T.3 判据与发现

1. **transition 陷阱**：控件带 `transition-[border-color,box-shadow]` —— focus 后**同步**读 computed `boxShadow` 读到的是**过渡起点（0px）**，而此时 `matches(':focus-visible')` 已经是 true。必须等过渡跑完（本脚本等 250ms）再读。推广：**"样式系统说没生效"先排除过渡中间态，再怀疑规则没命中。**
2. **基线只存度量值，恒真条件不进基线**：下限类断言（命中区 ≥44、ring 3px、圆角 =6px、控制台零噪声）是**每次都该成立的硬条件**，放进基线反而会把"违规值"固化成"合规基线"。比对与硬断言分开。
